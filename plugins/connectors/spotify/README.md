# Spotify Connector

Hermes-compatible portable plugin providing full Spotify Web API control in Vellum.

## Setup

1. Create a Spotify application at `https://developer.spotify.com/dashboard`.
2. Enable Web API and Web Playback SDK.
3. Register this redirect URI:

   `http://127.0.0.1:8000/api/plugins/spotify/oauth/callback`

4. In Vellum, open Settings → Plugins → Spotify, enter the public Client ID, and approve access.

PKCE is used, so no client secret is required. Credentials are stored locally at `data/plugins/spotify/auth.json` and are never exposed to the model.

If your account was connected before embedded playback was added, open the Spotify player and choose **Allow playback in Vellum**. Leave Client ID blank to reuse the existing app. Approve the new `streaming` and `user-read-email` scopes (the SDK also requires `user-read-private`).

Open the Spotify player, then click **Enable playback in Vellum** once to activate browser audio. After **Vellum player ready**, typed requests use the existing Spotify tools to search and play music on the registered **Vellum** Connect device. Neither Spotify Desktop nor Spotify's web player needs to be open. Keep the Vellum window open and the computer awake while listening; this is online streaming directly from Spotify.

## Embedded playback lifecycle

MusicAgent accepts up to eight typed actions together, such as `like this song and play the Spain songs` after showing Spain's chart, or `set volume to 25% and turn on shuffle`. Actions run in order with separate acknowledgements. Quotes and artist punctuation remain part of song searches. A current-song library edit joined with `and` captures the song playing when the request arrives; `play Blinding Lights then like this song` waits for the new track to appear in playback state before saving it.

Invalid control arguments are checked before any write. A failure, unresolved choice or confirmation preview stops the remaining actions and labels them as not run. Unverified playback is never replayed automatically and cannot cause a later step to save the preceding song. Playlist creation and mood suggestions retain their existing one-time approval. A new explicit library edit also removes an older pending song-edit target. Chart discovery stays available across library edits, volume and playback controls for its original 30-minute window; those controls do not extend the discovery's expiry.

`mute` sets the measured device volume to zero. `unmute` restores the verified pre-mute percentage recorded in this chat, on that same device; repeated mute commands preserve it. Missing or expired context asks for a percentage, and a device change requires an explicit target. `go back to the beginning of the song` seeks to zero within the current track. `what is the artist name of this song` reads current playback credits rather than the earlier conversation. Volume, seek and repeat acknowledgements require state read-back.

After `put this song on repeat`, `undo it` restores the preceding verified repeat mode (off, track or collection) on the same device. Failed or unverified repeat changes cannot authorize undo; repeating undo asks for an explicit mode. This uses the existing bounded conversation context, with no separate undo store.

Artist monthly-listener questions first delegate to MusicAgent's read-only `music_kworb` capability. It reads the public [Kworb listener table](https://kworb.net/spotify/listeners.html) directly, preserving artist identity, count, rank, source and retrieval date. Successful reads do not call a search provider. Unavailable or unlisted monthly-listener evidence falls back to the main Vellum agent's existing public-web tools and privacy-checked official-profile reader, without sending conversation history. Spotify followers are a different metric.

### Public music discovery

MusicAgent can answer `show top 10 artists`, `show songs by David Guetta`, `show top 5 songs in India today` and `show Japan weekly charts` using [Kworb's public Spotify statistics](https://kworb.net/spotify/). The answer displays the actual snapshot date even when the request says today. Only `play top 10 songs in India` starts playback, using the chart's exact track IDs through the existing Spotify integration; listing statistics leaves playback unchanged.

`find Drake latest albums` and `show previous albums by Drake` identify the artist, then read the paginated Spotify album catalog and verify release dates. Kworb's album pages rank streams and include compilations; they cannot establish the newest release or a complete discography. Its ranked artist list is also incomplete. Missing identities, unsupported countries and unrecognized page layouts return an evidence gap rather than guessed songs or counts.

The public reader accepts typed artist/country/period requests, never arbitrary URLs, and fetches only bounded HTTPS pages on `kworb.net/spotify/`. A process-local cache retains at most 16 public pages for six hours, keeping their original retrieval timestamps. Expired pages are refreshed; failed refreshes do not return cached counts as current. The tool receives no Spotify credentials, listening history or conversation transcript.

Country requests also accept `Show Japan’s weekly charts`, `play from the global charts`, `play songs from Japan` and `play a song from France`. After listing a chart, `play it` uses that displayed list's exact track URIs without fetching a different chart. Its source/date remain attached. Chart playback must read back a playing track from that list before reporting success; unavailable or unverified writes are never repeated automatically. An explicit later `play it` can retry the retained target. These references use the existing thread-scoped MusicAgent context and expire after 30 minutes.

After `find Post Malone latest album`, `what is the name of the album?` reads the verified discovery result and `play it` selects that album, with Spotify identity verification before the write. Several listed albums require a title. Bare artist questions such as `who is the artist?` read the current device, and `what album is this from?` reads its album metadata. They do not invent names when the live player has no metadata. Identically named Spotify artists can be distinguished by a corroborating Kworb artist ID; an uncorroborated identity remains ambiguous.

Open the UI through the local frontend server at `http://127.0.0.1:5173/design-uploads/Vellum%20Default%20Re-designed.html`. Direct `file://` HTML previews cannot receive SDK credentials because their `null` origin cannot be distinguished from an untrusted local file. The player offers a link to the served UI instead of asking for Spotify consent again.

The portable plugin's cached service owns the active Vellum device. Existing playback and queue tools default to this device; an explicit `device_id` remains supported. While Vellum playback is selected but unavailable, tools return a readiness error instead of switching to another device. Disable Vellum playback to return to the existing external-device controls.

`spotify.playback.session` is a typed, UI-only App Action for enabling/disabling the runtime. The SDK's `activateElement()` is invoked synchronously from the click before dispatch. Device registration, offline notifications and 20-second heartbeats are internal runtime lifecycle events, not user controls or stored preferences. They use typed API contracts and expire after 90 seconds. Only one window owns playback; another window must wait until the owner releases or expires. The local API runs as one process, as in the standard launcher.

Player buttons and quick typed controls such as `pause Spotify` use `spotify.playback.control` in the existing App Action runtime. A bare `pause` is recognized as music control only while this Vellum player is selected. Overlapping identical button requests are coalesced; conflicting controls are rejected until the current request finishes. No automatic replay follows an uncertain network failure.

Song, podcast, and playlist requests delegate to **MusicAgent** through the existing catalog and typed delegation runtime. Examples include `play Blinding Lights`, `Blinding Lights by The Weeknd on Spotify`, and `from my Hindi playlist play a song in shuffle order`. MusicAgent exclusively owns the Spotify skill and eight raw plugin tools; the UI retains its typed controls and SDK lifecycle access. The main agent sees the MusicAgent directory entry and delegates music work instead of discovering raw Spotify tools. Music requests also delegate when an unrelated specialist was previously selected, without changing that explicit selection. Playback responses bypass a second model rewrite and are never replayed from a specialist cache.

The provider-neutral `MusicPlan` and `MusicIntegration` interface allow another music service to supply an adapter and approved capabilities later. Only Spotify is connected now; requesting an unavailable service returns a connection limitation. Direct commands resolve without a model round trip. Less direct commands are parsed by the current local model into a schema-validated plan before any tool executes. Credentials, listening history and unrelated conversations do not enter that planner. Spotify reads are excluded from automatic Knowledge Core tool observation; explicit user preferences remain governed by the existing memory policies.

### Verified recall and suggest-first music

Questions such as `what song did u play from Drake yesterday?` read Spotify's available recently played records through the approved tool. Dates use the backend's local timezone (today, yesterday, or YYYY-MM-DD), and artist names must match the returned track credits. Retrieval is bounded to ten pages of fifty records; empty, malformed or missing history never becomes an invented song. Answers state that recent history is not a complete archive. This does not establish that a track was completed or that sound reached the speakers, and Spotify's endpoint does not include podcast episodes.

`remember I prefer instrumental music when working` writes only the user-authored statement to `agent:MusicAgent` in the existing Memory Orchestrator. It remains inspectable and removable through the existing memory UI, survives backend restarts, and is blocked when memory is off. Ordinary music feedback such as `I like mellow music when studying` goes through the existing pending-memory review flow. MusicAgent's read scopes are unchanged; it receives no unrestricted global memory or historical conversation transcript. The main agent may supply a brief relevant situation or user-stated preference with a delegation.

`suggest music for a stressful evening` uses a local, schema-validated planner to form a short catalogue search from that current request, bounded user context and approved saved music preferences. Catalogue results are resolved outside the model and previewed; `confirm` or `yes` plays the captured song followed by up to nine distinct playable catalogue results from that search, while `cancel` leaves playback unchanged. The preview states the continuation count. Acceptance makes one playback write without a new search. This is a bounded session, not unlimited radio: one available result has no continuation, and the queue stops when exhausted. A recommendation cannot be converted into playback by the planner. Search ranking does not prove emotional suitability. Mood interpretation remains tentative, and these suggestions do not constitute an autonomous recommendation engine or a learned profile from listening behavior.

After a successful playlist request, `recommend me` or `suggest a playlist` can offer that exact last-selected playlist in the existing conversation context. `suggest my Daily Mix 2` resolves a saved identity or a user-supplied link, then waits for acceptance before starting the full playlist context. Missing mixes ask for a link; a link supplied to a suggestion still produces a preview. No listening-frequency profile or claim about the user's most-used playlist is created.

Spotify catalogue results and history are not submitted to the music planner or background memory models. The background learner receives only the user's statement for music preference candidates, never the returned song/history or the assistant's interpretation. This boundary follows [Spotify's Developer Policy](https://developer.spotify.com/policy), including its restrictions on analyzing Spotify data to build profiles and ingesting Spotify content into AI models. Personal situation-to-music associations must come from the user's own statements, not inferred enjoyment or emotion from playback.

`play the next song` and `skip this song` are controls, not song searches. Playback-only turns are saved to the existing conversation checkpoint with their own acknowledgement. Song requests without an artist prefer the original studio recording using catalog version labels and earlier release dates. For example, `play Blinding Lights` selects The Weeknd ahead of Loi's later recording; explicitly requesting Loi or a remix retains that choice. Spotify exposes album release dates rather than an authoritative original-recording flag, so reissues, missing dates or equally early distinct artists can still require clarification. No artist is invented by the model.

An unresolved title offers artist choices before playback; `from Twenty One Pilots` or the artist's name applies to the preceding request using the shared thread context, expiring after 30 minutes and isolated by conversation. For `play Blinding Lights then set volume to 25% and turn on shuffle`, any necessary artist clarification retains the preflighted unfinished steps and resumes them after verified playback. Completed steps are not replayed, and captured `and` song references retain their original identity. The original continuation expiry does not extend on unclear replies. Cancellation, a replacing music request, errors and confirmation previews stop the tail; playlist-creation approvals are not bypassed. Attached chat context cannot divert an active clarification to the general model. This context is not a learned listening profile.

`play something from my Kannada playlist` resolves a unique matching playlist name, including names such as `Kannada bangers`. Multiple matches require clarification. Shuffle starts at a random playlist position. `play something from my Liked Songs` reads saved tracks rather than looking for a playlist named Liked Songs; it plays a bounded queue of up to 50 saved tracks, choosing a random library window for larger collections. The player refreshes its queue while open, takes upcoming-track updates from the SDK, and shows distinct upcoming tracks instead of copies of the current track. It shows an empty queue truthfully when Spotify supplies no upcoming tracks.

Named playlist matching applies to other playlists too. To create one, type `create a playlist called Night Drive with Blinding Lights by The Weeknd, As It Was by Harry Styles`. MusicAgent searches and previews the actual tracks before any write. Reply `confirm` to create the private playlist or `cancel` to discard the proposal. The existing pending-action store binds that approval to this conversation and consumes it once. Up to 50 requested songs are supported; missing names or song choices require clarification. A failed or uncertain write is reported honestly and is not retried automatically. The portable connector uses Spotify's current `POST /me/playlists` endpoint and the existing add-items endpoint.

`play the 1st song from the liked song playlist` uses Liked Songs in library order, with shuffle disabled before playback. `play something from my liked playlist` shuffles saved tracks. Playlist matching preserves emoji symbols (including emoji-only names), ignores presentation selectors, and paginates beyond 500 entries. `play my emoji playlist` selects only saved symbol-only names and asks when several match. Telugu/Telegu and Daily/Dalily spelling variants normalize for comparison; combined Tamil/Telugu names retain their actual identity. Missing saved playlists never fall back to public search. Daily Mixes absent from Spotify's saved-playlist response require their Spotify link. Spotify playlist links and URIs work directly and as follow-ups without a metadata preflight, since personalized mixes can return metadata 404 while still allowing playback. A link supplied after a named-playlist request binds that name to the URI in the existing thread context (at most five links, isolated by conversation, expiring after 30 minutes without a music turn); it creates no global alias store or listening profile.

`play a podcast from Nikhil Kamath` searches shows and starts the first playable episode returned by Spotify. `play a podcasts from WTF` asks which matching show; reply with its name or offered number. These choices use the existing bounded specialist context. Podcasts never fall back to music searches, and the SDK/player accepts episode metadata without song artist/album fields. Episode playback is subject to Spotify's actual device/content restrictions; a rejected command is reported as an error.

`how many playlists do I have?` and `show my playlists` read the complete saved list directly. Incomplete pagination fails rather than supplying a partial count. `what about my emoji playlist` shows saved symbol-only choices; reply with the exact emoji to play that identity. Common command typos such as `playlsit` and `playlis` are handled before song search. `reduce the volume to 10%` sets an absolute target; `increase the volume` increases it by ten percentage points, with measured read-back. After `skip 45 secs`, `go back the same amount` uses the last successful seek distance from this chat, even through an intervening music question. Missing or expired context asks for seconds instead of guessing; failed seeks do not replace the remembered interval.

`how many playlist I have saved?` and `retrieve my playlists` also use fresh saved-playlist reads, even with attached old conversation context. An unavailable API read is an error, never an invented zero. `play a random song from any of my saved playlists` selects a returned nonempty saved playlist and a random position with shuffle; it does not search for a playlist named "saved" or substitute a public one. A named request still matches that named saved identity. Additional `playlkist`/`playlits` typos normalize the collection word.

Song matching ignores a trailing `(with Artist)` only when Spotify actually credits that artist; remix and other version labels remain distinct. `play One Right Now` therefore resolves Post Malone/The Weeknd's catalog title. After a song or album followed by volume/shuffle controls, `no from psot malone` or `no from Drake` corrects that specific requested recording without another model turn. A bounded title-only search can recover a misspelled artist before enforcing the returned credits. Active controls preserve the reference across session reloads; changing to another collection or skipping clears old recording targets. An expired or missing target asks for the title immediately rather than reusing stale playback authority.

`play the Her Loss album`, `play Her Loss album by Drake` and `play the album Her Loss` are album operations. Different artists with identically named albums produce real artist choices; `by Drake` continues the album request. A collaborator name not present in Spotify's credits is not silently accepted. Playback uses the full verified album context and acknowledges its actual artists, including Drake and 21 Savage for Her Loss. It never falls back to a track search.

`no the album by ...` also repairs a recent older request that stored an explicit `... album` title as a song. If an incorrect artist filters the real album out of Spotify search, one title-only retry supplies actual album choices while retaining the requested artist check. Expired references still ask for the title; they do not grant playback authority to old context.

`can u play j cole latest album` and `latest album from lil baby` route directly to verified latest-album lookup. The browser recognizes these same playback forms and activates audio during the user's submission gesture, then waits for Vellum's registered device before sending chat. Catalog artist comparisons ignore punctuation while retaining non-Latin letters and artist IDs; multiple matching identities still require corroboration or clarification. `how many playlist is have?` also reads the saved collection rather than trusting old chat answers. Latest means a released full album returned by Spotify's artist catalog, with bounded complete pagination; it does not substitute a single or claim a latest release from an incomplete lookup.

The current device lease retains at most 32 health observations (SDK event name, relative timestamp, paused state, position and volume) and playback command counts. These appear as `web_playback` in the existing player response, contain no credentials, song metadata or conversation text, and disappear when the session is released or the API restarts. They help distinguish player errors and reconnects from duplicate commands; they do not prove sound reached the speakers.

The same trusted device endpoint accepts a bounded, transient SDK playback observation and measured volume from its current owner. Fresh observations (at most five seconds old) feed both current-song tools and the player; stale observations expire rather than becoming history or AI memory. A one-second local heartbeat samples the SDK without polling Spotify's remote API. Vellum device volume commands carry a unique request through this lease to `Spotify.Player.setVolume`, read `getVolume`, and wait up to five seconds for the exact acknowledgement. Unverified changes fail without replay; other Spotify devices retain Web API volume controls. The UI shows the measured percentage, supports keyboard adjustment, and preserves fresh local state against delayed remote snapshots.

`turn on shuffle`, `turn off shuffle`, and `put on the shuffle for this playlist` use typed shuffle controls and read-back. `increase the volume to max` and `set volume to maximum` target 100%. A truncated `increase the volume to ma` asks for clarification; `max` or `max*` completes that request in the same chat instead of claiming a change. Fresh SDK volume has its own expiry and remains controllable even when a paused player has no track snapshot. It cannot replace another device's reported volume or retain an expired measurement.

The SDK requests a fresh access token through the trusted local UI adapter whenever it needs one. Only the access token reaches the SDK, in memory; refresh tokens stay in the existing local store. The token endpoint checks client, Host, approved UI Origin and a non-simple header and returns `Cache-Control: no-store`. It is absent from model tool discovery and action receipts. SDK-rejected tokens trigger a refresh with a one-minute cooldown; repeated authentication failures require consent again. Connections have a timeout and exponential retry delay. Unsupported protected audio, Premium/account errors and autoplay rejection are shown explicitly.

Windows desktop uses Tauri/WebView2. Spotify documents browser support, not a guarantee for WebView2. Native protected-audio compatibility must pass a real playback check on the installed runtime; a successful frontend build or mock SDK test does not establish it. If initialization fails, Vellum reports the unsupported runtime. The browser-hosted Vellum UI can also use the same player on Spotify-supported browsers, but native desktop playback remains a separate acceptance gate.

Live acceptance: reconnect with the SDK scopes; keep Spotify closed; enable Vellum playback; play a track from typed chat; test pause/next and playlist shuffle; leave it running across token expiry; test network loss and sleep/wake; close/reopen Vellum and re-enable browser audio. Automated tests cover device routing, lease expiry/ownership, token refresh and lifecycle recovery. They do not prove audible playback or days/months of uptime.

Sources: [SDK reference](https://developer.spotify.com/documentation/web-playback-sdk/reference), [SDK setup](https://developer.spotify.com/documentation/web-playback-sdk/howtos/web-app-player), [WebView2 Widevine feedback](https://github.com/MicrosoftEdge/WebView2Feedback/issues/4828).

## Tools

MusicAgent interprets flexible wording with the selected local model and validates a typed plan before using these tools. `play a song from any playlist`, `choose any playlist u want`, and a fresh `any` after listing playlists select from the saved library. Small whole-command typos such as `paues` remain controls. An explicit emoji playlist name is retained exactly; a model-generated playlist/track ID never overrides catalog resolution. Artist-only requests such as `play a song from 69` select a playable song with verified 6ix9ine credits; `my 69 playlist` remains a named saved playlist request.

Successful skip/previous UI receipts update the existing scoped MusicAgent context, so a subsequent `go back` means previous track. Beginning/restart and explicit seconds remain separate controls. YT Music/player and YT player identify YouTube Music; unavailable integrations report that state instead of controlling Spotify. Polite/casual Spotify playback requests activate and register the SDK under the submit gesture before chat is sent. A local-model persona evaluation is available in `scripts/verify-music-language.py`; its read-only interpretation results do not establish audible playback or long-term uptime.

Spotify Free supports search and read-oriented library features. Premium is required for playback mutations, queue additions, and device transfer. The embedded SDK supplies Vellum's Connect device; external-device mode requires another active Spotify device.
