# Personal hosted YouTube receiver — 17 October 2026

## Implemented and activated

The personal Cloudflare Worker and D1 buffer are deployed in the user's account
with a persistent workers.dev origin and a once-per-minute Cron trigger. No
paid-plan upgrade, custom domain purchase or Git publication was performed.
Wrangler authorization was completed by the user with account/user read,
workers_scripts write and D1 write scopes. Billing data was not readable with
these deliberately limited scopes; this verification is not an account invoice.

The receiver is a public-event transport, not a hosted Vellum agent or a
multi-tenant service. Its authenticated manifest contains only channel IDs and
per-channel callback credentials. D1 retains at most seven days, 20,000 events
or 64 MiB of raw payload. Existing local Knowledge Core, upload outbox,
duration/relevance policy and AutomationStore remain canonical. The local client
uses the existing scheduler, bounded authenticated sync and durable checkpoints.

Google's subscription snapshot was refreshed through the existing OAuth owner:
**289 saved subscriptions**, **285 eligible after current exclusions**, plus
**17 additional tracked creators**, yielding **302 eligible push channels**.
This was not a claim that the account has 302 saved subscriptions.

Google verified **all 302 of 302 hosted subscriptions**, with zero pending at
the final frontend/API check. Cron registration advanced while the local API
was offline. The connection dialog identifies hosted collection, catch-up
retention, last sync and the saved-versus-monitored counts.

## Duration allowance and retry repair

The existing local duration budget had already reached **200 of 200 checks for
2026-10-17** before the hosted notification test. This is Vellum's configured
daily allowance, not a demonstrated exhaustion of Google's project quota or a
Cloudflare hosting limit. Usage counters were preserved. Uncached duration
checks must wait for the next UTC day (**18 October, 05:30 IST**).

The live investigation found that unresolved metadata retried too often and the
fast worker also enriched quiet baseline records. The fast path now validates
pending uploads only. Unknown duration retries start at two minutes and back off
to one hour; RSS may enrich recent baseline records on its slower cadence.
The idle fast worker skips expensive full-profile rebuilding when duration is
waiting for backoff, provider recovery or daily allowance. A twelve-hour
regression test stays below twenty unresolved-video calls, and a quota-deferred
worker test rejects repeated profile rebuilding. These changes do not trust
unknown duration or relax the strictly-over-three-minute policy.

The live replay validates offline collection, durable catch-up and duplicate
suppression using previously verified metadata. A brand-new uncached upload
passing the live duration gate after this deployment has not yet been verified;
the exhausted current-day allowance is reported in the UI. Unit tests exercise
new-event delivery, short/unknown holds and failure recovery.
