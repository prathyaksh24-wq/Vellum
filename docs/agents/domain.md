# Domain Docs

Vellum uses a single-context domain model.

## Before exploring

Read:

- `CONTEXT.md`
- Relevant decisions under `docs/adr/`

If either path does not exist, proceed silently. Domain-modeling creates files lazily when terminology or decisions are resolved.

## Vocabulary

Use the canonical terms defined in `CONTEXT.md` in specifications, tickets, tests and implementation.

If a needed concept is absent, resolve it through domain-modeling instead of silently inventing competing terminology.

## Decisions

If proposed work contradicts an existing ADR, surface the conflict explicitly rather than silently overriding it.
